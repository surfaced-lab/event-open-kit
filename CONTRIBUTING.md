# Contributing

Thank you for helping improve Event Open Kit.

## Before opening a pull request

1. Open an issue for a behavior change, new pattern, or content addition.
2. Keep the change focused and explain the user problem it solves.
3. Use synthetic names, dates, locations, URLs, and counts only.
4. Run `npm test` and include the result in the pull request description.
5. Check that no `.env`, credentials, private mailbox material, customer data, or unlicensed media is included.

## Pull requests

Use a branch named `feature/<short-name>`, `fix/<short-name>`, or `docs/<short-name>`. The first line of the pull request description should say what changed. Include screenshots for visible UI changes and describe desktop/mobile behavior.

Maintainers may ask for a smaller change when a pull request mixes product code, private operational logic, and public examples. The public boundary is a feature of this project.
